robot-arm-sim · technical documentation

Robot Arm Kinematics Simulator

A browser-based simulator for arbitrary serial robot arms. Define any number of revolute and prismatic joints, edit Denavit–Hartenberg parameters live, and get real-time forward kinematics, numerical inverse kinematics, DOF analysis and floor/self collision limits — no build step, no backend.

Live demo ↗ Source code Test suite (50 tests)

Overview

Everything runs client-side as ES modules — three.js renders, plain JavaScript does the math.

Free-form chains

Add, remove and reorder revolute & prismatic joints. Edit all four DH parameters (θ₀, d, a, α) plus joint limits per joint — the scene, DH table and DOF count update instantly.

Inverse kinematics

Two numerical solvers (damped least-squares + cyclic coordinate descent) with structured restarts, a collision-aware validity filter and smooth joint-space easing toward solutions.

Collision limits

Floor plane, non-adjacent link pairs, adjacent-link fold-over and joint-body proximity — slider moves bisect to the wall, IK solutions are validated before acceptance.

Zero-dependency deploy

Static files on GitHub Pages. three.js loads from CDN via an import map with version-pinned URLs; the math core has no dependencies at all and runs in Node for tests.

The mathematics

All kinematics follow the standard Denavit–Hartenberg convention.

Forward kinematics

Each joint contributes one homogeneous transform from four parameters — fixed offset θ₀, d, link length a, twist α — and one variable (θ for revolute, d for prismatic):

$$ {}^{i-1}A_i = \operatorname{Rot}_z(\theta_i^*)\, \operatorname{Trans}_z(d_i)\, \operatorname{Trans}_x(a_i)\, \operatorname{Rot}_x(\alpha_i) $$

The end-effector pose chains them: TEE = A₁ · A₂ · … · An, evaluated in forwardKinematics(). Orientation readout is roll–pitch–yaw extracted from the rotation block. Degrees of freedom use the Grübler–Kutzbach count, which reduces to the number of actuated joints for an open serial chain.

Inverse kinematics — damped least squares

Arbitrary DH chains have no general closed-form IK, so the solver is numerical. The position Jacobian $J \in \mathbb{R}^{3 \times n}$ is computed by central finite differences; each iteration steps the joints by the damped pseudo-inverse:

$$ \Delta q = J^{T}\,(J J^{T} + \lambda^{2} I)^{-1}\, e, \qquad e = p_{\text{target}} - p_{\text{EE}} $$

Only the inner 3×3 system is solved directly (Gaussian elimination with partial pivoting), and per-iteration joint velocity is capped for stability. Damping λ = 0.05 keeps the step well-conditioned near singularities.

Cyclic coordinate descent (CCD)

A second, geometric solver walks the chain tip-to-base and rotates each joint about its axis to align the joint→end-effector vector with the joint→target vector. CCD escapes folded / wrong-branch configurations that pure gradient descent cannot, so every restart seed is tried with CCD first and refined with DLS.

Restarts, limits and validity

  • Limits: revolute joints spanning a full rotation wrap through ±π (they can pass the seam); joints with a real sub-2π range and all prismatic joints clamp.
  • Seeds: current pose → base azimuth to the target (and the opposite branch) → base flip → sign flip → deterministic pseudo-random spreads. A 60 ms budget keeps live dragging responsive.
  • Validity: solveIK accepts an optional validate(q) predicate. The UI passes the collision check, so the solver keeps hunting until a branch is both converged and collision-free — only falling back to a colliding solution when every converged branch fails.
  • Motion: accepted solutions ease toward the goal exponentially in joint space along the shortest wrap-aware path, so the arm glides instead of snapping.

Collision geometry

Links are treated as capsules (radius 0.022 m), joints as spheres (0.05 m). Checks per configuration:

link ↔ floorsegment endpoint / closest-point z below −tolerancecenterline-based; small tolerance avoids locking ground-level poses

Architecture

Five ES modules, one responsibility each. The math core never touches the DOM or three.js — that's what makes it unit-testable in Node.

index.html→main.js (scene + wiring)→ ui.js (panel)↔dh.jsik.jscollision.js↔arm.js (three.js)
ModuleResponsibility
dh.jsJoint model, DH transform, FK chain, Grübler DOF, DH table, RPY extraction, presets
ik.jsPosition Jacobian (finite differences), DLS descent, CCD descent, seed/restart strategy, validate() filtering
collision.jsCapsule/sphere collision queries (floor, self, fold, joint bodies), human-readable descriptions
arm.jsthree.js scene graph: link/joint meshes per DH frame, target marker + axes, collision tinting, geometry disposal on rebuild
ui.jsJoint editor cards, collision-aware sliders (bisect to wall), IK controls + status, FK/DH readouts, HUD, animation follower
main.jsRenderer, lights, grid, orbit controls, panel hookup
The viewport is y-up while DH convention is z-up: the arm group is rotated −90° about x, and the target marker converts through localToWorld — getting this space conversion right was one of the real bugs found during development.

Using the simulator

  • Build a chain: load a preset or add revolute/prismatic joints; edit name, type, DH params and slider limits on each card.
  • Drive joints: drag sliders, type values, or hit the 0°/±90°/180° snap chips. With collision limits on, motion bisects to the contact point.
  • IK target: drag the X/Y/Z target sliders (or numbers). Arm follows target solves continuously; Solve IK solves on demand. The marker's RGB arrows show the DH frame.
  • Read the math: live DOF + EE pose in the viewport HUD and panel, plus the generated DH table with the variable of each joint marked.
  • Frames toggle: show/hide RGB axis triads at every DH frame; Reset view restores the camera.

Testing

50 unit tests run in Node's built-in runner — no dependencies, no DOM needed since the math core is pure.

git clone https://github.com/rabahdj2002/robot-arm-sim.git
cd robot-arm-sim
node --test tests/*.test.js   # 50 passing

tests/dh.test.js

Matrix identity/-0 handling, known FK configurations, rotation orthonormality, mutation cases: empty chain, single joint, 1–8 mixed chains, mid-chain and first-joint removal.

tests/ik.test.js

Convergence on 2R/6R, joint-limit respect, ±π wrap-through, wrong-side base recovery, elbow branch flips, restricted-limit clamping, validate() branch selection and fallback.

tests/collision.test.js

Floor detection both directions, adjacency exemption, degenerate links, all presets collision-free at defaults, joint-body checks, candidate-pose override.
